# Enhancement ideas spotted while working (2026-09-06)

Running list, per Jay's ask. Each is something I saw in the code or data, not a guess.

1. **Two compare pages for the same rivalry.** `/compare/starship-vs-new-glenn` AND `/compare/spacex-starship-vs-new-glenn` both exist with near-identical titles — the same query-split that hurt Blue Origin vs SpaceX. One should canonical to (or 301 into) the other.
2. **Stale product names in titles.** `starlink-vs-kuiper` still says "Kuiper" (Amazon renamed it Amazon Leo); the schedule guide's milestones said "Project Kuiper" (fixed today). Worth a sweep: grep "Kuiper" outside historical context.
3. **43 of 44 compare pages have no FAQ schema**, and ~a third have no number in the title. Roadmap #13's second half. Do the launch/telecom ones first.
4. **Schedule guide title vs H1 mismatch.** Title says "Cape Canaveral Launch Schedule: 150+ in 2026"; H1 says "2026 Space Launch Schedule: Every Mission This Year". Kept the title (it is what ranks) and added a real "From Cape Canaveral" live block so the page delivers on it — but the mismatch is worth a GSC look: which query family actually lands here?
5. **`dateModified: new Date()` is a pattern**, not a one-off. Found on the two carrier guides and the Blue Origin guide; likely elsewhere. `grep -rn "dateModified: new Date" src/app` and fix the rest.
6. **Rocket pages have no alert form.** LaunchWatchForm supports a `rocket` scope but is only embedded on launch, site and city pages. A "email me every Falcon 9 launch" form on `/rockets/[slug]` is a one-liner and a strong retention hook.
7. **Mission Control's "How to track" copy in the schedule guide told people to "enable push notifications"** — the no-account email alert is the real product. Fixed in the guide; check the FAQ page and onboarding for the same stale instruction.
8. **The rail's "Track it after liftoff" goes to `/satellites` generically.** Once a payload has a NORAD id it could deep-link to that object. Needs a mapping we don't keep yet.
9. **Launch calendar could power an `/embed/launch-calendar` widget** the way cadence has one — free distribution.
10. **`SITE_STATS.launches2025`** is a hardcoded record; the cadence lib already computes last year's total. Derive it.
11. **Page metadata silently overrides layout metadata.** Several compare pages define `metadata` in both `layout.tsx` and `page.tsx`; Next lets the page win, so a retitle in the layout does nothing. Caught by the production probe on four pages. A guard test that fails when both files export metadata would prevent the next one.
12. **The manifest lumps undated launches into the last month.** The calendar showed Oct 9, Nov 7, Dec 78 — the December figure is mostly "NET Q4" placeholders. Worth splitting "dated" from "month-only" launches in the calendar so the December card doesn't imply a real surge.
13. **Every "Cost:" line in the old tourism post was a year stale within six months.** Content with prices needs the same `PRICES_AS_OF` + source-per-row discipline the new guide has; the launch-cost guide already does this with `LAUNCH_COST_AS_OF`. Candidates: the space-tourism tool page (`/space-tourism`), the Virgin Galactic / Blue Origin company profiles.
14. **Our own pages contradicted each other on New Glenn** (guide: "lost in April"; status compare: "pad lost in May"; spec compare: "NG-1 Oct 2025"). A single `src/lib/vehicle-status.ts` fact sheet per vehicle (last flight, status, next milestone, as-of date) that the guide, both compares and the rocket page all read would make that impossible.
15. **Blog posts have no `redirectedTo`/`hidden` field**, so retiring one means deleting the object. A field the listing and sitemap respect would make promotions like the tourism one a two-line change.
