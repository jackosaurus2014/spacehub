# Space Tycoon graphics review — 2026-09-12

Read-only review by a design agent on 2026-09-12: rendering stack in `src/components/game/` (SolarMap3D.tsx, SolarSystemCanvas.tsx, SolarMapBloom.tsx, MapCommandCenter.tsx, GameStyles.tsx, RegionBackdrop.tsx, GalacticMapView.tsx, map/LocationDetailConsole.tsx), `src/lib/game/{assets,orbital-elements,map-bodies}.ts`, `src/lib/three-runtime.ts`, `scripts/generate-art.ts`, the VISUAL_DEPTH / VISUAL_AAA / GAME_DESIGN_REVIEW docs; then production played headlessly (New Game → Command → Map → Build) at 1366×900 and 390×844 with all `/api/space-tycoon` POSTs aborted.

## (a) Assessment

**Stack as found.** Desktop map = R3F `<Canvas>` (SolarMap3D.tsx:1725): fov 50, dpr [1,2], one `pointLight` at the Sun (decay 0) + ambient 0.38, `meshStandardMaterial` roughness 0.92 on NASA equirects (`public/textures`, 3.9 MB), Earth clouds + night emissive, BackSide atmosphere shells from the `ATMOSPHERES` table, drei `Stars` (4,200), a 2048×1024 nebula skybox at intensity 0.18 (22 KB, effectively invisible), 550 instanced icosahedron belt rocks, canvas-sprite labels, `OrbitControls` with zoomToCursor, and a lazy selective-bloom chunk (SolarMapBloom.tsx, 73 KB) gated on dpr>1, FX pref and not reduced-motion. No tone-mapping override (R3F default ACES). Positions come from log-scaled Keplerian-ish elements (`orbital-elements.ts`) on a free-running real-time clock: presentation only, not the game calendar. Phones (<768px), reduced-motion, no-WebGL2 and user preference get the 2D canvas (SolarSystemCanvas.tsx: 1536² sprites + radial-gradient limb darkening). `use3DCapable` starts false, so every desktop load mounts the 2D renderer first and then swaps; the network log shows both `/game/texture-*.webp` sprites and `/textures/*.webp` downloaded. Galactic layer is DOM/SVG parallax; location detail is SVG.

Bundle (prod, decoded): game page chunk 2.5 MB (642 KB wire), three core 351 KB, R3F 148 KB, bloom 73 KB; desktop total JS 5.9 MB vs mobile 4.0 MB (mobile never fetches the three chunks, verified). Textures fetched on map open ≈3.3 MB.

**Strengths.** The start-menu hero and Build cards (Gemini art) are genuinely good; the radial command menu on phone is the best "game" moment in the flow; map-as-stage (panels overlay a dimmed, frozen map) is the right architecture; belt instancing, lazy bloom, reduced-motion handling (Stars speed 0, damping/trails off, stardust static) and the shared 2D/3D derivations (map-modes/map-zoom/map-bodies) are well engineered; the ConsolePanel/DataTable kit gives the Dashboard a real console feel.

**Top 5 visual problems.**
1. **The game lives inside a website.** At 1366×900 there are 339 px of chrome above the map (site ticker, site nav, ResourceBar, Frontier band, hub bar, sub-view row); the 3D stage is 1066×561 with a 300 px Outliner. No immersive/fullscreen mode exists (page.tsx, layout.tsx, Navigation.tsx). The site nav's "Markets" collides with the game hub "Markets": a probe click opened the site dropdown over the game.
2. **Mobile map is unreadable.** Map starts at y=350 of 844, then three stacked pill rows (layer / mode / zoom) plus the Lanes/Ships/World toggles (`MapCommandCenter.tsx:790`, `w-[min(92vw,300px)] flex flex-col`, bottom-16) sit over the planets, and the PWA banner covers the bottom. The 2D system is essentially hidden.
3. **The 3D system is flat and small.** Default camera [0,30,44] renders Earth at ~6 px; the sun is a textured sphere with a sprite glow; the skybox is black. Labels collide at rest (Enceladus/Titan, Lunar Orbit/Moon, Ganymede/Callisto/Jupiter/Europa/Io) and are drawn in "Inter" (SolarMap3D.tsx:196), a font the site never loads, so they fall back to system-ui while the HUD is Orbitron/DM Sans.
4. **"Earth command center" is a text panel.** DashboardPanel is a card grid titled COMMAND CENTER with a mission clock; no Earth, no room, no holographic briefing. The 22nd-century fiction is carried only by CSS corner brackets and the start menu.
5. **Type floor and region identity.** Computed styles: 10 px is the modal text size in the game (97 leaf nodes at 10 px, 55 at 11, 4 at 7.2). Region identity is a CSS radial tint (RegionBackdrop); seven outer bodies share `planet-ice.webp`, and `REGION_ASSETS` (assets.ts:309) has no consumer in `src/components/game` or `src/app/space-tycoon`. Emoji remain in the map bar ("📡 Activity", "✦ Spatial").

Benchmark: Stellaris/EVE win on a persistent bezel with the world always visible; Elite's galaxy map and KSP 2 win on a scale-honest, glowing, orbit-annotated system; Homeworld/Dyson Sphere win on lighting and volumetric backdrop. We have the information-architecture pieces; we lack stage size, light, scale and a place.

## (c) Sequence

- **Phase 1 (≈35 h, highest perceived upgrade per hour):** 5 bridge mode + mobile overlay fix, 8 lighting, 9 framing, 11 asset budget, 10 type/icon floor. Ships in one week; the map roughly doubles in size and stops looking like a widget.
- **Phase 2 (≈80 h):** 6 labels, 4 region skyboxes/particles, 3 planet shaders, 7 instanced objects. This is where "flying over the belt feels different from Venus" becomes true.
- **Phase 3 (≈90 h):** 1 ephemeris + scrubber (also a real gameplay-intelligence feature: launch windows as chokepoints), then 2 the holographic deck.

## (d) Risks

- **Bundle:** the page chunk is already 2.5 MB decoded; keep every 3D addition behind the `dynamic(() => import('./SolarMap3D'))` boundary (MapCommandCenter.tsx:21) so mobile keeps never fetching three; troika Text adds ~100 KB, GLTFLoader ~40 KB.
- **Phone GPU:** 3D is off below 768 px; if it is ever enabled there, cap dpr 1.5, no bloom, instancing only. Today three animation loops can run at once on desktop (WebGL frameloop, StardustLayer rAF, and on phones the 2D canvas rAF).
- **SSR/hydration:** `use3DCapable` intentionally starts false; any new R3F surface must be `ssr:false`, never touch `window` in render, and honour the `THREE_D_ENABLED` kill switch (three-runtime.ts exists because R3F v8 on React 19 took the whole page down on 9/3). drei `<View>` needs one fixed Canvas with `eventSource`, which fights the measured-height map container and the `covered` → `frameloop='never'` gating; plan it explicitly.
- **Parity contract:** every 3D feature needs a 2D counterpart or an explicit "decorative-only" ruling, or the two renderers will drift.
- **Codebase friction:** GameStyles.tsx is a 2,101-line styled-jsx global (CSS payload already 345 KB); the design-system migration is only through Dashboard (296 hex literals elsewhere): add colours only via tokens. Site nav/game hub name collisions and the missing immersive mode are product decisions, not just CSS.
- **QA:** anonymous games POST to the live world; every graphics probe must abort non-GET `/api/space-tycoon/` requests.
